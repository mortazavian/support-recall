# راهنمای قالب‌های ورود داده

همه نمونه‌های این پوشه ساختگی‌اند و اطلاعات مشتری واقعی ندارند. می‌توانید آن‌ها را از صفحه «مدیریت دانش» دریافت کنید. فایل‌ها باید با پسوند `.csv`، `.json` یا `.txt` باشند، حداکثر ۵ مگابایت حجم داشته باشند و بیش از ۲۰۰۰ گفت‌وگو نداشته باشند.

## CSV

هر سطر یک پرسش و پاسخ است. در پیش‌نمایش، ستون پرسش و پاسخ را انتخاب کنید؛ ستون‌های شناسه، تاریخ، محصول و دسته‌بندی اختیاری‌اند و در صورت وجود می‌توانید آن‌ها را هم نگاشت کنید. عنوان ستون‌ها می‌تواند فارسی یا انگلیسی باشد. فایل UTF-8 و UTF-8 دارای BOM پذیرفته می‌شود؛ فایل CSV ویندوزی با رمزگذاری فارسی Windows-1256 نیز خوانده می‌شود.

ستون‌های نمونه:

| ستون | نیاز | نمونه |
|---|---|---|
| شناسه گفت‌وگو | اختیاری | پشتیبانی-نمونه-۰۰۱ |
| تاریخ | اختیاری | `2026-10-05` |
| محصول | اختیاری | اپلیکیشن فروشگاه |
| دسته‌بندی | اختیاری | پرداخت |
| پرسش مشتری | الزامی | پرداخت من ناموفق بود اما مبلغ از حسابم کم شد. |
| پاسخ پشتیبانی | الزامی | مبلغ‌های ناموفق پس از بررسی بانک بازگردانده می‌شوند. |

هر سطر CSV به دو پیام مرتب‌شده تبدیل می‌شود: مشتری سپس پشتیبانی. خانه‌های پرسش و پاسخ نباید خالی باشند.

## JSON

فایل JSON باید آرایه‌ای از گفت‌وگوها باشد. هر گفت‌وگو یکی از دو شکل زیر را دارد. نام کلیدها ثابت و انگلیسی است؛ مقدارهای متنی می‌توانند فارسی باشند.

### یک پرسش و پاسخ

```json
[
  {
    "conversation_id": "پشتیبانی-نمونه-۱۰۱",
    "date": "2026-10-07",
    "product": "اپلیکیشن فروشگاه",
    "category": "پرداخت",
    "question": "چطور رسید پرداخت را دریافت کنم؟",
    "answer": "از بخش سفارش‌ها رسید را دریافت کنید."
  }
]
```

### پیام‌های مرتب‌شده

```json
[
  {
    "conversation_id": "پشتیبانی-نمونه-۱۰۲",
    "messages": [
      {"role": "customer", "content": "مرسوله من کجاست؟"},
      {"role": "support", "content": "شماره سفارش را می‌فرمایید؟"},
      {"role": "customer", "content": "شماره سفارش ۴۵۷۲ است."},
      {"role": "support", "content": "مرسوله امروز به مرکز توزیع رسیده است."}
    ]
  }
]
```

برای هر پیام، `role` یکی از `customer` یا `support` و `content` متن غیرخالی است. هر گفت‌وگو باید دست‌کم یک پیام از هر نقش داشته باشد. `conversation_id`، `date`، `product` و `category` اختیاری‌اند.

## متن ساده

فایل متنی از بلوک‌های گفت‌وگو تشکیل می‌شود. خط `---` بلوک‌ها را جدا می‌کند. هر خط، یک مشخصه یا یک پیام است و باید یک عنوان فارسی، دونقطه و مقدار داشته باشد. هر پیام در یک خط می‌آید.

عنوان‌های شناخته‌شده:

- `گفتگو:` یا `شناسه گفتگو:` برای شناسه گفت‌وگو
- `تاریخ:` برای تاریخ اختیاری
- `محصول:` و `دسته‌بندی:` برای اطلاعات اختیاری
- `مشتری:` و `پشتیبانی:` برای پیام‌ها

نمونه:

```text
گفتگو: پشتیبانی-نمونه-۲۰۱
تاریخ: 2026-10-09
محصول: حساب کاربری
دسته‌بندی: امنیت
مشتری: چطور رمز عبورم را عوض کنم؟
پشتیبانی: از تنظیمات حساب گزینه تغییر رمز عبور را انتخاب کنید.
---
گفتگو: پشتیبانی-نمونه-۲۰۲
مشتری: آیا می‌توانم نشانی سفارش را تغییر دهم؟
پشتیبانی: تا پیش از تحویل به پست، نشانی را ویرایش کنید.
```

هر بلوک باید دست‌کم یک پیام مشتری و یک پیام پشتیبانی داشته باشد. تاریخ باید به‌صورت ISO مانند `2026-10-09` یا زمان ISO نوشته شود. تاریخ‌های خالی حدس زده نمی‌شوند.

## پیش‌نمایش و خطاها

ابتدا فایل تجزیه و اعتبارسنجی می‌شود؛ هنوز منبعی در کتابخانه ذخیره نمی‌شود. برای CSV، پس از انتخاب ستون‌ها پیش‌نمایش را دوباره بگیرید. فقط با زدن «ورود به کتابخانه» ذخیره انجام می‌شود. خطاهای ساختار فایل، ستون‌های لازم، تاریخ و پیام‌های خالی به فارسی نمایش داده می‌شوند. ورود دوباره محتوای یکسان، منبع تکراری ایجاد نمی‌کند.
